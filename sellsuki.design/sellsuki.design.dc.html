Set up

ที่อยู่ repo, สิ่งที่ต้อง copy และลำดับการติดตั้งจนใช้ component ตัวแรกได้

Repository
hostgitlab.sellsuki.com (internal — ต้องอยู่ใน VPN) pathsellsuki/share/sellsuki-components package@sellsuki-org/sellsuki-components version0.27.1-beta.1 techLit 3 · TypeScript · Vite · Storybook 7
ถ้าคุณเป็น UXUI

ไม่ต้อง clone ก็ได้ — ดู component ที่มีจริงใน Storybook แล้วออกแบบด้วย token จากหน้า Tokens; ต้อง clone เมื่อจะแก้ token หรือ docs

ข้าม step 2 ไปที่ step 5 ได้เลย
ถ้าคุณเป็น DEV

ทำ step 1 → 4 ให้ครบก่อนเขียนหน้าจอแรก ห้าม copy CSS ของ component ออกมาแก้เอง ให้ override ผ่าน token เท่านั้น

ทำตามลำดับทั้งหมด
1 Clone repo 
git clone git@gitlab.sellsuki.com:sellsuki/share/sellsuki-components.git
cd sellsuki-components
npm install
2 ติดตั้งใน project ของคุณ 
npm i @sellsuki-org/sellsuki-components@0.27.1-beta.1
ยังต้องยืนยันว่า package อยู่ registry ตัวไหน — ถ้ายังไม่ publish ให้ติดตั้งจาก git โดยตรง: npm i git+ssh://git@gitlab.sellsuki.com/sellsuki/share/sellsuki-components.git#v0.27.1-beta.1
3 Import ครั้งเดียวที่ entry ของ app 
import "@sellsuki-org/sellsuki-components";
import "@sellsuki-org/sellsuki-components/style.css";
บรรทัดแรก register custom element ทั้งหมด บรรทัดที่สองคือ token และ font — ขาดบรรทัดใดบรรทัดหนึ่ง component จะไม่ขึ้นหรือขึ้นแบบไม่มีสไตล์
4 ครอบ provider แล้วใช้ component ตัวแรก 
{{ setupUsageCode }}
component อ่าน theme จาก context — ถ้าไม่ครอบ ssk-theme-provider สีและ typography จะกลับไปเป็นค่า default ของ browser
5 เปิด Storybook ดูของจริง 
npm run storybook   # → http://localhost:6006
path ที่ต้องรู้ใน repo
src/elements/primitive — button, badge, input, text src/components/ประกอบแล้ว — table, modal, sidebar src/contexts/theme/default.tstoken ทั้งชุด (แก้สีหรือ type ที่นี่) src/types/theme.tsunion ของ props ทุกตัว src/main.tsรายการ export — tag ที่ไม่อยู่ที่นี่คือใช้ไม่ได้ claude-templates/template ให้ agent scaffold component

Pattern IDs

รูปแบบ ID ที่ใช้เรียก pattern แต่ละตัว — dev เอาไปอ้างในโค้ด ticket หรือ comment ได้ตรง ๆ โดยไม่ต้องเปิดตารางเทียบชื่อ

Base ID — ตัว pattern เอง

<ชื่อ-semantic>-<เลข 3 หลัก> เช่น list-page-106 — pattern ทุกตัวใช้ได้กับทุก brand อยู่แล้ว เลขจึงเป็นแค่ลำดับที่เดินต่อกันไป ไม่ได้บอกแบรนด์ใด ๆ ชื่อด้านหน้าให้คนอ่านรู้ทันทีว่าเป็น pattern อะไร ส่วนเลขเป็นตัวอ้างอิงที่ตายตัว

Instance ID — ตอนหยิบไปใช้จริง

พอเอา pattern ไปครอบเนื้อหาของฟีเจอร์จริงในแบรนด์ใดแบรนด์หนึ่ง ให้ต่อท้าย Base ID ด้วยเลขแบรนด์อีก 1 หลัก (ดูตารางด้านล่าง) กลายเป็น Instance ID ของหน้านั้นโดยเฉพาะ — spec ของ pattern ยังอ้างด้วย Base ID เหมือนเดิม Instance ID มีไว้บอกว่า "หน้าไหนของแบรนด์ไหน" เท่านั้น

list-page-106 + 1 = list-page-1061 — Member List ระบบ CRM (oc2plus)
list-page-106 + 2 = list-page-1062 — Order List ระบบ OMS (patona)
